# S1 — аудит RU/KK строк и звука

Снимок на 2026-08-24, ветка `levels-premium-pass`. Изначально был аудит без
правок (см. §6 для истории), затем в этом же проходе синхронизирован
голосовой пак — дрейф, найденный аудитом, закрыт.

---

## 1. Как это устроено (для контекста)

Локализация в игре живёт в **трёх независимых местах**, каждое со своим способом хранения RU/KK:

1. **`src/i18n/index.ts`** — словарь `t(lang, key)` для UI-хрома (кнопки, шапка,
   настройки, гейты). 58 ключей в `ru`, 58 в `kk` — **полный паритет**, утечек
   не найдено.
2. **Инлайновые RU/KK-объекты в компонентах** — например `WelcomeScreen.tsx`
   (`copy.forestText`, `copy.iceText`, `copy.cityText`, ...) и
   `TravelMapScreen.tsx` (`CHAPTERS[].name.ru/.kk`). Тот же принцип, что и
   `t()`, но без общего словаря — паритет проверен точечно, утечек не найдено,
   но это второй источник правды, за которым никто централизованно не следит.
3. **`this.copy(ru, kk)` в 3D-сценах** (`BaseLevelScene.ts:3401`) — диалоги,
   HUD-реплики, названия целей. Метод берёт `this.lang`, который сцена
   получает один раз в `scene.init(nick, lang, onHud)`. Строго типизирован:
   оба литерала обязательны в каждом вызове.

Озвучка (`AudioManager.tts`) работает поверх (3): `scripts/extract-voice-lines.mjs`
сканирует все файлы `src/three/scenes/*.ts`, находит каждый `copy(ru, kk)`,
хэширует нормализованный текст в id (`voiceLines.ts: lineId`) и пишет
`public/assets/voice/manifest.json`. `scripts/synth-voice.mjs` рендерит
недостающие клипы через `say` (голоса Milena/ru и Aru/kk, оба стоят на этой
машине) + ffmpeg → `public/assets/voice/{ru,kk}/<id>.mp3`.

В браузере `AudioManager.tts(text, lang, nick)` сперва ищет готовый клип по
`lineId(text, lang, nick)`; если файла нет или он не проигрался — откатывается
на `window.speechSynthesis` (`speakWithBrowser`).

## 2. «Не путать RU-голос с KK» — проверено, путаницы нет

Проверил путь `hud.line` → `AudioManager.tts`:

- `MissionScreen.tsx` и `Mission0Screen.tsx` держат `lang` из `useUIStore` и
  вызывают `AudioManager.tts(hud.line, lang, player?.nick)` в одном и том же
  `useEffect`. И текст (`hud.line`, который сцена сформировала через
  `this.copy(ru, kk)`), и `lang`, переданный в `tts()`, — из одного и того же
  значения `lang`.
- Смена языка на лету **не** оставляет сцену с текстом одного языка и вызовом
  `tts()` с другим: эффект инициализации сцены в обоих экранах имеет `lang` в
  списке зависимостей (`MissionScreen.tsx:127`), поэтому смена языка
  полностью **пересоздаёт сцену** (`scene.dispose()` → новый `scene.init(...,
  lang, ...)`). Тяжеловесно, но именно поэтому рассинхрона текст/озвучка не
  бывает — `this.lang` в сцене и `lang` в HUD-эффекте физически не могут
  разойтись.
- `AudioManager.tts()` сам строит путь клипа как `${VOICE_BASE}${lang}/${id}.mp3`
  — папка `ru/` или `kk/` берётся из того же аргумента `lang`, что и текст,
  так что RU-клип для KK-реплики физически не может быть запрошен.
- Деградация без готового клипа (`speakWithBrowser`) тоже не подменяет язык:
  для `kk` без системного `kk-KZ`-голоса текст **транслитерируется**
  (`approximateKazakhForRuVoice`) и читается русским голосом — акцент, но те
  же казахские слова, а не русский текст. Если нет и русского голоса —
  используется тишина (`return`), сознательно, см. комментарий в
  `AudioManager.ts:475-481`.

Единственное место, которое **не** проходит через эту гарантию:
`SettingsPanel.tsx:43` — `AudioManager.tts(ru ? 'Озвучка включена' : 'Дауыс
қосылды', lang)`. `ru`/`lang` берутся из одного и того же `useUIStore` стейта,
так что подмены языка тут тоже нет — но строка живёт вне
`src/three/scenes/*.ts`, поэтому экстрактор её не видит (см. §1) и она всегда
идёт через браузерный TTS, даже когда для всего остального в игре есть готовый
пак.

**Итог: подмены RU-голоса на KK-реплику или наоборот в текущем коде нет.**

## 3. Голосовой пак: дрейф закрыт (было 46+46 непроигранных, сейчас 0)

Первый проход аудита (снимок раньше в тот же день) нашёл, что диалоги в
сценах разошлись с `public/assets/voice/manifest.json` на **46 RU + 46 KK**
новых/изменённых реплик — свежий контент по хабу/городу и юрте/домбре/саду в
лесном мире, ещё не прошедший `synth-voice.mjs`. Пока клипов не было,
эти реплики **молча** уходили в `speakWithBrowser` — на Android для KK это
либо тишина, либо транслитерация русским голосом (см. §2), то есть ребёнок
не слышал свежие реплики на казахском вообще, либо слышал их с акцентом.

**В этом проходе синхронизировано:**

```bash
node scripts/extract-voice-lines.mjs   # manifest.json: 645 → 714 клипов
node scripts/synth-voice.mjs           # отрендерил недостающие клипы
```

`node scripts/extract-voice-lines.mjs --check` → **up to date (714 clips)**.

Также удалено **85 осиротевших клипов** (`ru`: 43, `kk`: 42) —
`.mp3`-файлы в `public/assets/voice/{ru,kk}/`, для которых в манифесте больше
нет записи (реплики переписаны/удалены в предыдущих коммитах по хабу и
уровням, старые файлы оставались на диске). Проверено скриптом, который
сверяет каждый файл с `manifest.json.lines` — 0 orphans, 0 missing после
чистки.

**Текущее состояние (проверено):**

| | RU | KK |
|---|---|---|
| записей в manifest.json | 359 | 355 |
| файлов на диске | 359 | 355 |
| отсутствующих клипов | 0 | 0 |
| осиротевших файлов | 0 | 0 |

Пак весит 10.0 MB на 714 клипов (было 5.5+5.5=11 MB с осиротевшими файлами —
чистка их снизила).

## 4. Процесс: добавлена `voice:check`, но не в build

`package.json` получил `"voice:check": "node scripts/extract-voice-lines.mjs
--check"` — можно звать вручную или из будущего CI. **Не** добавлял вызов в
`build`/`type-check`: в репозитории нет `.github/workflows`, и несколько
ролей (`levels-forest`, `levels-ice`) сейчас активно правят `copy(ru, kk)` в
сценах в этой же ветке. Если бы `voice:check` падал сборку при любом
несинхронизированном тексте, это блокировало бы их работу до отдельного
прохода `audio-i18n` — а рендер клипов требует `say`/ffmpeg на машине,
которых нет гарантированно у каждого агента. Рекомендация лиду: включать в
CI, когда он появится, с shared-раннером, где стоит бэкенд синтеза.

## 5. SFX — что реально есть

Все SFX процедурные (Web Audio API, осцилляторы), файлов нет — см.
`AudioManager.ts:214-297` и уже описано в `docs/VOICEOVER_TOOLS.md`. В типе
`SfxName` объявлено 15 звуков, использовано в коде — 14:

| SFX | Где вызывается | Звук |
|---|---|---|
| `collect` | сбор фрукта/звезды (все Level-сцены) | тон 523→784 Hz вверх |
| `bonus` | бонус-предмет, `Level11Scene` прыжок в воздухе | тройной восходящий аккорд |
| `interact` | нажатие E/Space, `Mission1Scene` тяга | короткий клик 440→550 Hz |
| `success` | успешное действие, `Mission1Scene` завершение тяги | мажорное трезвучие |
| `stumble` | ошибка/спотыкание | нисходящий sawtooth 200→100 Hz |
| `found` | найден NPC/ёжик, `phase === 'lanterns'/'mend'/'*found*'/'*arrived*'` | восходящая мелодия из 4 нот |
| `click` | клики кнопок UI (`SettingsPanel` и др.) | тон 800 Hz, 40 мс |
| `whoosh` | переход/движение | свист 300→600 Hz |
| `sparkle` | искры/эффекты, `Level0Scene` близость к цели, `Level11Scene` в полёте | аккорд 1047/1319/1568 Hz |
| `levelComplete` | завершение уровня (`phase === 'outro'`) | фанфары, 4 ноты |
| `tick` | появление интеракта, `Level0Scene` вдали от цели | тон 1200 Hz, 30 мс |
| `stepGrass` | шаг по траве (`BaseLevelScene.updateFootstep*`) | триангл 120–175 Hz |
| `stepSnow` | шаг по снегу | триангл 170–210 Hz |
| `stepStone` | шаг по камню | square 145–190 Hz |
| `step` | объявлен в `SfxName`, **нигде не вызывается** — мёртвый код (заменён на `stepGrass/stepSnow/stepStone` после ввода поверхностей) | — |

Музыка (`playMusic`) — три процедурных темы: `forest`, `ice`, `hub`, плюс
`none`. Выбор темы по уровню — `musicForLevel(levelId)`: `>= 10` → `ice`,
иначе `forest` (согласуется с каноном GDD: L0–9 лес, L10–16 лёд,
`CLAUDE.md`).

`step` как мёртвый код не трогал — удаление типа/enum-значения выходит за
рамки audio-i18n зоны (`src/audio/**` не в списке зон роли), да и цена
хранения одного неиспользуемого литерала в объединении типов нулевая.
