планки качества флагманского уровня Mission 0.

Meshy/3D-художник, чистая topology, rig и набор idle/walk/run/celebrate.

## 5. Дизайн-столпы

Каждый уровень обязан:

1. Рассказывать историю дружбы через помощь.
2. Вводить одну новую механику.
3. Обучать по правилу: показать, попробовать, повторить с усложнением.
4. Не иметь fail-state и наказания.
5. Иметь ясный critical path и небольшой golden path.
6. Давать фидбек на каждое действие: анимация, частицы и звук.
7. Завершаться эмоциональной наградой и связкой со следующим уровнем.
8. Занимать 3–5 минут при первом прохождении, без искусственного растягивания.

Стиль: добрый современный soft-3D для детей, не Roblox-клон, не low-poly demo,
не набор случайных CC0-моделей.

## 6. План работ

### Этап 0. Зафиксировать baseline

1. Запустить `npm run type-check` и `npm run build`.
2. Пройти Mission 0 и уровни 1–4 без изменений.
3. Снять скриншоты desktop `1280x720` и mobile portrait `390x844`.
4. Записать:
   - длительность каждого уровня;
   - FPS desktop/mobile;
   - soft-lock, клиппинг камеры, перекрытия HUD;
   - отсутствие/повторы звуков;
   - несоответствия RU/KK.

Не начинать визуальный рефакторинг без baseline.

### Этап 1. Общая инфраструктура

До точечной доводки уровней проверить, что `BaseLevelScene` даёт всем сценам:

- единый hero loader и locomotion;
- общий camera follow;
- joystick + WASD + arrows;
- единые guide arrow, interaction marker и particles;
- общий quality preset desktop/mobile;
- корректный dispose geometry/material/texture;
- единое подключение музыки, SFX и TTS;
- одинаковую структуру HUD.

Не копировать большие блоки Mission 0 в каждый уровень. Выносить только реально
повторяемые части. Terrain/grass/water подключать выборочно: механика и читаемость
важнее количества эффектов.

### Этап 2. Уровень 1 — «Первый друг»

Файлы:

- `src/three/scenes/Mission1Scene.ts`
- `src/components/Mission1Screen.tsx`
- `src/components/MissionScreen.tsx`

Канон:

- пройти тропу и ручей;
- три раза освободить фрукт;
- липкие нити заранее намекают на Путало;
- познакомиться с Айей и пригласить её в Город Друзей.

Требования:

- механика освобождения фрукта должна иметь три читаемых шага;
- каждый шаг визуально отличается и даёт squash, particles и SFX;
- Айя видна до финального диалога как цель/ландмарка;
- ручей и мост читаются, но не становятся отдельной сложной механикой;
- финал добавляет Айю в друзей и ведёт к яблоневому саду;
- диалоги короткие, добрые, одинаково понятные на RU/KK.

### Этап 3. Уровень 2 — «Яблоневый сад»

Файлы:

- `src/three/scenes/Level2Scene.ts`
- `src/components/Mission2Screen.tsx`

Текущие фазы:

```text
intro -> demo -> collect -> sort -> outro
```

Канон:

- садовник показывает правильную сортировку;
- игрок пробует на одном яблоке;
- затем сортирует остальные;
- сад визуально оживает;
- critical path: 6 яблок;
- bonus: до 10 яблок.

Требования:

- цвет корзины нельзя передавать только цветом: добавить форму/иконку;
- неправильное яблоко мягко отскакивает и остаётся доступным;
- нельзя потерять яблоко или получить soft-lock;
- корзина реагирует анимацией и звуком;
- лучи/кольца показывают правильную цель;
- финальный «сад ожил» заметно меняет свет, насыщенность и окружение;
- финальный диалог ведёт к старому дубу и потерявшемуся ёжику.

### Этап 4. Уровень 3 — «Потерявшийся ёжик»

Файлы:

- `src/three/scenes/Level3Scene.ts`
- `src/components/Mission3Screen.tsx`

Текущие фазы:

```text
intro -> search -> found -> outro
```

Канон:

- старый дуб виден из любой точки;
- поиск проходит в трёх секторах;
- два сектора дают бонус/улику;
- в третьем находится ёжик;
- следы, шорох и визуальные подсказки работают вместе.

Требования:

- игрок не должен искать случайно в одинаковых кустах;
- каждый сектор имеет уникальный силуэт и окружение;
- пустой сектор не является наказанием и даёт маленькую награду;
- звук не может быть единственной подсказкой;
- ёжик получает idle, реакцию на игрока и эмоциональный момент находки;
- финал добавляет Ёжика в друзей и упоминает качающийся мост.

### Этап 5. Уровень 4 — «Качающийся мостик»

Файлы:

- `src/three/scenes/Level4Scene.ts`
- `src/components/Mission4Screen.tsx`

Текущие фазы:

```text
intro -> bridge -> crossed -> outro
```

Канон:

- мост состоит из пяти секций;
- безопасное окно показано светом и движением;
- первая секция обучает медленно;
- следующие секции комбинируют ритмы;
- ошибка не сбрасывает уровень и не роняет игрока.

Требования:

- мост физически и визуально остаётся читаемым на мобильном;
- камера не клиппит мост, тросы и края ущелья;
- безопасное состояние нельзя передавать только красным/зелёным цветом;
- при ошибке Барсик пошатывается и остаётся на последней безопасной секции;
- секции нельзя пропустить обходом или перескочить из-за collision bug;
- Айя видна на противоположном берегу;
- финал ведёт к уровню с Белочкой.

## 7. Арт и ассеты

Приоритет источников:

1. Наши финальные брендовые модели.
2. Meshy для уникальных персонажей и ключевых пропов.
3. Kenney/Quaternius CC0 для фоновых модульных объектов.
4. TRELLIS/Hunyuan только для прототипов и сравнения.

Не смешивать случайные стили. Для уровней 1–4 собрать один forest kit:

- яблони и кусты;
- 3 типа камней;
- 2–3 типа брёвен;
- единые цветы/тюльпаны;
- корзины;
- старый дуб;
- подвесной мост;
- яблоки трёх цветов;
- уникальные модели Айи и Ёжика.

Каждый новый внешний ассет зарегистрировать в `docs/licenses/ASSETS_3D.md`.
Не использовать чужой IP, NC-лицензии или ассеты без явной коммерческой лицензии.

Бюджет для браузера:

- финальный игровой персонаж желательно до 50–80k вершин;
- prop обычно до 2–15k вершин;
- текстуры чаще 512–1024, 2K только для героя/крупной ландмарки;
- повторяемые объекты инстансить;
- bloom отключать или уменьшать на mobile;
- pixel ratio ограничивать;
- grass density и shadow map снижать на mobile.

- музыка Фруктового леса;
- шаги по земле и мосту;
- сбор/успех/мягкая ошибка;
- скрип мостика;

- короткие VO ключевых реплик RU/KK.

Рекомендуемый сервис озвучки: ElevenLabs. Сначала проверить произношение RU и KK
на тестовых репликах. Если KK звучит неверно, не публиковать машинную озвучку:
оставить субтитры или привлечь носителя.

Аудио предгенерировать и хранить как оптимизированные файлы. Не вызывать TTS API
из клиента во время каждого прохождения.

## 9. UX и доступность

- Подсказка управления показывается до первого реального движения.
- На touch-устройствах не показывать WASD поверх джойстика.
- Нижняя диалоговая карточка не перекрывает героя и цель.
- Текст крупный, максимум 1–2 коротких предложения.
- Иконка дублирует текстовую цель.
- Цвет никогда не является единственным каналом информации.
- Уважать mute, volume, TTS и `prefers-reduced-motion`.
- Не использовать ежедневные навязчивые уведомления.

## 10. Приёмка каждого уровня

Уровень готов только если:

- проходит от начала до конца без перезагрузки;
- нет soft-lock, тупиков и потерянных collectible;
- есть правило трёх и минимум три gameplay beat;
- есть signposting без обязательного чтения длинного текста;
- все действия имеют визуальный и звуковой фидбек;
- работает RU и KK;
- управление работает клавиатурой и джойстиком;
- desktop держит около 60 FPS;
- средний телефон держит не менее 30 FPS;
- HUD не перекрывает действие в `390x844`;
- камера не проходит через крупные объекты;
- dispose не оставляет сцену, аудио или RAF после выхода;
- `npm run type-check` проходит;
- `npm run build` проходит;
- сняты desktop и mobile скриншоты;
- зафиксированы фактическая длительность и найденные ограничения.
