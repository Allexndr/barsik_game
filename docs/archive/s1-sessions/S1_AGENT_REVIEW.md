### Конфликт, который стоит вынести в `Blocked` — `vercel.json` Cache-Control

`vercel.json`: заголовок `/assets/(.*)` поменялся с
`public, max-age=31536000, immutable` на `public, max-age=86400,
must-revalidate`. Это **не сопровождается записью на борде** ни от кого.

Проблема: `/assets/` — это как раз тот путь, где по `.vercelignore`-комментарию
(до правки) лежали тяжёлые GLB/webp-модели («2.1 GB Blender/Meshy originals»).
Снятие `immutable`/`max-age=31536000` со **всего** `/assets/(.*)` ради починки
кеша трёх картинок на лендинге (которые чинятся точечно через `?v=` — уже
сделано, см. выше) — это глобальный даунгрейд кеш-политики ради локальной
проблемы. Эффект: каждый повторный визит на сайт будет ре-валидировать
(условный GET) все ассеты каждые 24 часа вместо года — на мобильном интернете
это лишние round-trips для тяжёлых 3D-моделей, которые физически не меняются
между релизами так часто. Точечный фикс (versioned query string / хэш в имени
файла для лендинг-картинок, как уже сделано в WelcomeScreen/TravelMapScreen)
устраняет проблему без изменения глобальной политики.

Выношу в `Blocked` на борде с тегом `@barsik-lead` — нужно решение: либо
откатить `vercel.json` к `immutable`, раз точечный `?v=` фикс уже покрывает
исходную проблему, либо явно подтвердить, что глобальное снятие `immutable`
было осознанным трейд-оффом (и тогда закрыть находку).
