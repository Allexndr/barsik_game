## 4. Story arc Сезона 1

### Логлайн

Барсик просыпается во Фруктовом лесу и узнаёт, что фрукты перестали расти. Помогая садовнику и новым друзьям, он следует липким нитям одинокого фотографа Путало, понимает, что тот не злодей, и вместе устраивает лесной праздник. После QR-сундука друзья уходят в Ледяную долину: снег, лёд, забота о тепле — и финальный зимний сундук с картой к Горному озеру (S2 teaser).

### Две арки

**Arc 1A — Фруктовый лес (L0–9)**  
Тема: знакомство, помощь, эмпатия к «страшному».  
Эмоция: «ты нужен, тебя любят».

**Arc 1B — Ледяная долина (L10–16)**  
Тема: прощание с теплом, новые вызовы, забота о друге.  
Эмоция: рост, уверенность, праздничный финал.

## 5. Design pillars

1. **Дружба через помощь** — каждый уровень = помочь кому-то (narrative anchor).
2. **Приглашение, не принуждение** — мир зовёт любопытством; no fail-state.
3. **Мастерство через правило трёх** — показать → попробовать → повторить/усложнить; одна новая механика за уровень.
4. **Игрок лучше персонажа** — радость и фэнтези; якорь «ты добрый, ты справился».
5. **Эмпатия к «злодею»** — Путало не враг.
6. **Signposting без текста** — свет, цвет, ландмарки, силуэты.
7. **Juice на каждое действие** — частицы + звук + анимация.

## 7. Спецификация по уровням

Общие QA для каждого уровня (дополняют per-level):

- [ ] Critical path не теряется; golden path визуально отличен
- [ ] 4–6 мин первое прохождение (плейтест)
- [ ] Нет soft-lock; мягкий retry сегмента
- [ ] RU + KK тексты из `levels.ts` / GDD; без утёкших языков
- [ ] `dispose()` без утечек при выходе
- [ ] 60 fps desktop / ≥30 fps mobile
- [ ] Mute + `prefers-reduced-motion` respected

| 3–7: минимум текста, крупные иконки, короткое обучение, VO, отсутствие сложных меню | Обязательно | интервью 16.07 |
| 7–10: полноценные квесты, коллекции, дом, друзья, простые загадки | Обязательно | интервью 16.07 |
| 11+: более глубокие диалоги, исследование, социальные и сезонные цели без инфантилизации | Требует отдельного UX-pass | интервью 16.07 |
| Образовательная ценность и понятная польза для родителя должны быть сформулированы для каждой когорты | Обязательно для презентации и onboarding | WhatsApp 17.07 |

**Решение по текущей сборке:** игровой контент S1 оптимизирован для ядра 5–12, но UI и сценарии не должны блокировать расширение на 3–7 и 11+. Перед релизом нужен отдельный age-adaptive UX-spec.

### 17.2 Аккаунт, сохранение и возврат

| Требование | Приёмка |
|------------|---------|
| Ник и базовый образ создаются быстро; обычная регистрация не стоит перед первой игрой | Игрок входит в M0 без обязательного телефона/email |
| Телефон используется мягко: восстановление прогресса, родительский контакт и уведомления | Можно пропустить; повторный запрос после ценностного момента |
| Прогресс сохраняется между устройствами и сезонами | Дом, друзья, декор, звёзды, QR-награды, предметы и сезонные флаги не сбрасываются |
| Длинный эпизод можно продолжить в другой вечер | Сохраняется checkpoint текущего beat, а не только завершённый уровень |
| Дата рождения после подтверждения не меняется ребёнком | Родительское редактирование; основа birthday reward |
| Возвратные уведомления не отправляются ежедневно | Мягкий push примерно после 3 дней отсутствия; частота ограничена |
| Уведомление не давит и не стыдит | Формулировка: друг скучает / в городе произошло доброе событие |

### 17.3 Город Друзей, дом и поведение друзей

Первичные интервью задают **Город Друзей как центральное место возврата**, а карту - как способ путешествия. Текущая S1-сборка использует TravelMap как основной хаб; это техническое состояние, а не окончательное продуктовое решение.

| Система | Требование |
|---------|------------|
| Центральный хаб | После уровня игрок возвращается в Город Друзей или видит явный переход туда; карта доступна из города |
| Рост города | Город растёт автоматически по мере прогресса: дома, парк, кафе, деревья, аттракционы, фонтан, спортивные зоны |
| Дом игрока | Игрок сам выбирает и размещает декор собственного дома/двора |
| Друзья | Не ходят толпой за Барсиком; ждут на своих местах в городе/дворе и реагируют на возвращение |
| Ежедневные изменения | В городе периодически появляется небольшое видимое событие: новый объект, реплика, украшение, гость |
| Самовыражение | Дом, профиль, одежда/аксессуары и в будущем флаг команды; базовый Барсик не привязан навсегда к красной кепке |

**Открыто:** `Town first` против `Map first` должно быть подтверждено владельцем после UX-прототипа. До решения нельзя выдавать TravelMap за окончательный канон.

### 17.4 Свобода исследования и прогресс персонажа

- Игрок может идти по ясному быстрому critical path или исследовать безопасные боковые зоны.
- Линейная последовательность уровней не должна превращать мир в меню-коридор; после S1 допустим выбор доступной арки/мира.
- Барсик получает постоянные способности и инструменты: улучшенный прыжок, взаимодействие, водный транспорт, сезонные предметы.
- Друзья могут давать earned-abilities, но не должны продавать силу за деньги.
- Ошибка не отнимает прогресс; сегмент перезапускается с понятного checkpoint.
- Новая способность сначала показывается, затем тренируется по правилу трёх.

### 17.5 Социальные и кооперативные системы

Социальный слой является долгосрочной целью, но требует отдельного child-safety ТЗ.

| Этап | Функция | Ограничения |
|------|---------|-------------|
| S1 foundation | Приглашение реального друга по безопасной ссылке/коду | Без открытого чата; родительские ограничения |
| S2 candidate | Async-help, совместные цели, подарки без торговли | Нельзя передавать валюту/редкие QR-призы |
| S2/S3 | Команды, общий флаг, помощь в строительстве, командные события | Friendly ranking; сезонный или периодический reset |
| S3 research | Мини-кооп «позови друга» | Модерация, privacy, блокировка/жалоба обязательны |
| Отдельный проект | Текстовый/голосовой чат | Не включать без политики безопасности, модерации и согласия родителя |

### 17.6 QR, упаковка и награды

| Требование | Решение |
|------------|---------|
| QR расположен **внутри упаковки** и подтверждает покупку продукта | Не печатать основной игровой QR как открытый промо-код снаружи |
| Производственный сценарий допускает один код на тираж/партию, если уникальная печать невозможна | Backend должен уметь ограничивать злоупотребление без обещания уникального кода на каждую пачку |
| Сканирование открывает сундук/награду, а не просто запускает игру | Deep link ведёт в безопасный QR flow после входа |
| QR-награда никогда не бывает пустой | Гарантирован минимум косметики/звёзд/декора |
| Дубликат заменяется эквивалентной наградой | Таблица duplicate compensation обязательна |
| Пулы разделены по сезонам и SKU | Состав пула, rarity, срок и fallback версионируются |
| QR не pay-to-win | Сила и прохождение доступны без покупки |
| Редкий вечный приз возможен | Вероятности и правила акции прозрачны и согласованы юридически |

**S1:** L9 и L16 остаются демонстрационными сюжетными сундуками. Реальная упаковочная интеграция включается только после утверждения механики партий, антифрода и правил акции.

### 17.7 Live-service, календарь и офлайн

В первичных материалах встречаются две модели сезона: **квартальная** из раннего плана и **6–8 недель** из более поздней сезонной рамки. До подтверждения владельцем длительность не фиксируется.

| Ритм | Контент |
|------|---------|
| Ежедневно/через вход | Небольшой бонус или изменение города; без обязательной серии |
| Еженедельно | Короткая арка/испытание и общая добрая цель |
| Раз в 2 недели | Косметика/декор |
| Ежемесячно | Персонаж, тематическое событие или праздник |
| Сезон | Мир/арка, 2–4 значимых друга как рабочий ориентир, QR-пул, оформление упаковки |
| Полгода/год | Крупное расширение мира и систем - только по метрикам |

Дополнительно:

- Новый год и день рождения - приоритетные события; birthday reward не должен требовать покупки.
- Темы будущих сезонов проверяются через детские тесты, опросы родителей и данные конверсии.
- Офлайн 1–2 раза за сезон: фото с маскотом, семейное задание, выставка рисунков, экологическая/благотворительная активность.
- Маскот-события не превращаются в ежедневный шум.

### 17.8 Admin, аналитика и бизнес-приёмка

| Область | Требование |
|---------|------------|
| Content admin | Управление уровнями, друзьями, QR-сериями, пулами наград, событиями и промо без пересборки клиента |
| Player support | Просмотр прогресса, восстановление сейва, блокировка злоупотреблений |
| Аналитика | Новые/активные игроки, completion по beat/уровню, retention D1/D3/D7/D30, возвраты, ошибки и FPS |
| QR | Сканирования по SKU/партии/сезону, первая и повторная активация, duplicate compensation |
| Социальное | Приглашения, принятые приглашения, командная активность, жалобы |
| Бизнес-воронка | Вовлечение -> удержание -> приглашение -> QR/повторная покупка |
| Решение о продолжении | Масштаб S2/S3 утверждается по качеству S1 и метрикам, а не автоматически |
| CRM/официальный сайт | Игра интегрируется с официальной коммуникацией бренда без рекламного давления на ребёнка |

### 17.9 Production-процесс сценариев

- Каждый уровень согласуется итеративно: synopsis -> beats -> blockout -> playable -> art/audio -> QA.
- Для ключевой сцены фиксируются позиции персонажей, направление взгляда, одежда/аксессуары, состояние окружения и переход к следующему beat.
- Сценарий проверяется отдельно по возрастным когортам и RU/KK.
- Нельзя объявлять уровень завершённым только потому, что он запускается.
